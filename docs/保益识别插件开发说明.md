# 保益识别插件开发说明

## 1. 插件概述

保益识别插件用于扩展保益悦听的图片文字识别、图片描述、图片问答和图标识别能力。一个插件可以提供多个引擎，每个引擎声明自己的名称和能力标志。

推荐识别插件上架悦听商店。开发者可以通过悦听商店实用工具创建插件程序包，用户可在悦听商店浏览、安装和更新插件。

悦听商店实用工具下载地址：[点击此处下载](https://api.gitcode.com/api/v5/repos/gcw_SpGZ48lW/baoyi/releases/yt-app-store-utility-20260701/attach_files/YtAppStoreUtility.zip/download)

### 1.1 插件形式和目录

- 类型：32 位 Windows DLL，与读屏主程序架构一致。
- 主 DLL 文件名：以 `BoyRecog` 开头，例如 `BoyRecogExample.dll`。
- 安装目录：`%APPDATA%\BoyPcReader\plugins\Recognition\插件文件夹\`。
- 每个插件一个文件夹，主 DLL 放在该文件夹根目录，可同时包含依赖库、模型和默认配置模板。用户配置必须保存到下述独立配置目录。
- 插件名称取自 DLL 版本资源的 `ProductName`，插件版本取自 `ProductVersion`，两项均不能为空。
- 引擎名称和能力通过导出函数获取。

```text
%APPDATA%\BoyPcReader\plugins\Recognition\
    ExamplePlugin\
        BoyRecogExample.dll
        依赖文件和模型
    AnotherPlugin\
        BoyRecogAnother.dll
```

### 1.2 配置保存目录

插件的用户配置必须保存到当前 Windows 用户的“文档”目录下：

```text
<文档目录>\BoyPcReader\plugins\Recognition\<插件目录名>\
```

`<插件目录名>` 必须与插件安装目录中的文件夹名称一致，不是 DLL 文件名、版本资源中的 `ProductName` 或引擎名称。例如安装目录为 `%APPDATA%\BoyPcReader\plugins\Recognition\ExamplePlugin\` 时，配置目录为 `<文档目录>\BoyPcReader\plugins\Recognition\ExamplePlugin\`。

应使用 Windows 已知文件夹接口获取当前用户的实际文档目录，例如 `SHGetKnownFolderPath(FOLDERID_Documents, ...)`，不要硬编码 `C:\Users\用户名\Documents`，也不要假设文档目录始终位于 `%USERPROFILE%\Documents`。文档目录可能被用户迁移或重定向。插件自行创建所需子目录、读取及保存配置；一个插件包含多个引擎时，可在自己的配置目录内按引擎组织配置。

插件安装目录用于存放程序和随包资源，不用于保存用户修改后的配置。安装更新会替换插件目录，并可能使用 `.new`、`.old` 临时目录；用户配置应始终保存在上述独立目录，以便升级后继续使用。

### 1.3 发现和加载规则

读屏只扫描 `Recognition` 下的一级子目录，忽略以 `.new`、`.old` 结尾的目录。每个插件目录只查找当前目录中的 `BoyRecog*.dll`，不递归查找，只取第一个匹配文件。因此一个目录应只放一个符合该名称规则的主 DLL。

主 DLL 文件名按不区分大小写去重，插件名称也不能重复；重复时只加载先发现的插件。目录名不要求与 DLL 文件名或插件名称相同。

初始化、退出清理和获取引擎列表是必需导出。五个执行接口按插件提供的能力导出；缺少某个执行接口时，读屏会移除对应能力，而不是直接判定整个插件无效。具体规则见第 6 节。`BoyRecogSettings` 为可选的引擎设置接口，缺少该接口不影响识别能力和插件加载。

## 2. 通用约定

### 2.1 ABI 和返回值

- 所有导出函数名称固定，以 `BoyRecog` 开头，必须通过 `extern "C"` 导出。
- 所有导出函数及回调函数采用 `__cdecl` 调用约定。
- DLL 导出表中的名称必须与本文完全一致，不带 C++ 名字修饰或额外前缀。建议使用 `.def` 文件明确导出名称。
- 所有导出函数返回 `int`：`0` 表示成功，非 `0` 表示失败，包括初始化和退出清理。
- 非零错误码由插件自行定义，读屏不统一解释不同插件的错误码。
- 接口不跨 DLL 边界传递 STL 容器、C++ 对象或异常。
- 结构体统一使用 `#pragma pack(push, 8)` 定义，并在定义结束后恢复对齐方式。

### 2.2 同步调用和内存生命周期

所有接口均为同步调用。执行函数返回时，识别及本次调用的全部回调均已结束，不能返回后继续回调。

回调在调用导出函数的线程中执行。插件可以在内部并行处理，但必须在返回前完成处理，并在调用线程交付结果。读屏应在工作线程调用耗时识别接口。插件使用的网络请求应有有限超时，超时返回非零错误码。

输入指针由调用方管理，只保证在本次导出函数调用期间有效。输出指针由插件管理，只保证在对应回调期间有效，包含数组内嵌的字符串指针。读屏需要保留结果时必须在回调期间复制。双方不得释放对方的内存，因此不提供结果释放接口。

`userData` 是调用方提供的不透明指针，允许为 `nullptr`。插件必须原样传给每次回调，不解释、不修改、不释放。

初始化成功后才能调用引擎列表、设置或执行接口。卸载前先等待正在执行的调用和回调结束，再调用退出清理。执行接口可能被不同工作线程调用，插件应保护共享状态；不支持并行的引擎可以在内部串行执行。调用方不要在结果回调中重入同一插件或卸载插件。

### 2.3 图片和字符串

所有执行接口使用以下图片参数：

```cpp
const char* imageData;
size_t imageSize;
```

- `imageData` 指向完整图片文件的编码数据，不是文件路径、Base64 字符串或原始像素。
- 数据可以包含 `\0`，必须按 `imageSize` 读取，不能使用 `strlen`。
- 插件不得修改输入数据，也不得在函数返回后保留输入指针。
- 空指针、零长度、损坏或不支持的图片格式应返回非零错误码。
- 插件的所有引擎及其支持的图片识别接口都必须支持 PNG 图片编码数据。
- 插件可以额外支持其他图片格式，并在插件说明中列明。

引擎名称、提示词、消息文本和返回文本均采用以 `L'\0'` 结尾的 UTF-16 `const wchar_t*`。Windows 下 `wchar_t` 为 16 位。引擎名称必须非空，在同一插件内唯一且稳定；执行接口必须使用引擎列表返回的名称精确匹配，不得自行切换其他引擎。读屏通过插件及其引擎名称共同定位引擎。

### 2.4 结果和失败语义

- 纯文本 OCR 和图标识别接口成功时回调一次，返回完整文本；成功但无结果时传空字符串，不传空指针。
- 引擎列表成功时回调一次，返回完整列表，允许空列表。
- 结构化接口按阅读顺序为每个结果项回调一次，允许零个结果项。
- 纯文本 OCR、图标识别或引擎列表接口失败时不调用结果回调。
- 简短图片描述成功时只回调一次完整结果，`done` 必须为 `true`，不允许分段回调。
- 详细图片描述和图片问答允许分段回调，成功时最后一次回调设置 `done == true`；中途失败可以已有部分文本，最终以函数返回值判断成功。失败的部分回答不能作为完整助手消息加入后续历史。
- 结构化接口可能在已回调部分项目后失败。最终返回非零时，读屏必须丢弃本次已经收到的所有项目。
- 是否成功最终以导出函数返回值为准，不能仅以收到回调作为成功依据。

## 3. 数据结构和能力标志

以下公共定义可放入插件头文件。结构体字段只包含固定宽度整数、指针和 `size_t`；没有需要调用方构造或释放的对象。

```cpp
#include <stddef.h>
#include <stdint.h>

typedef uint64_t BoyRecogCapabilities;
typedef int32_t BoyRecogItemType;
typedef int32_t BoyRecogDescriptionDetail;
typedef int32_t BoyRecogMessageRole;

enum : BoyRecogCapabilities
{
    BOY_RECOG_CAP_OCR             = 1ULL,
    BOY_RECOG_CAP_AUTO_OCR        = 2ULL,
    BOY_RECOG_CAP_PDF_OCR         = 4ULL,
    BOY_RECOG_CAP_OCR_POSITION    = 32ULL,
    BOY_RECOG_CAP_OCR_OTHER_TYPES = 64ULL,
    BOY_RECOG_CAP_IMAGE_BRIEF     = 512ULL,
    BOY_RECOG_CAP_IMAGE_DETAILED  = 1024ULL,
    BOY_RECOG_CAP_ICON           = 8192ULL
};

enum : BoyRecogItemType
{
    BOY_RECOG_ITEM_ICON            = 0,
    BOY_RECOG_ITEM_ICON_WITH_LABEL = 1,
    BOY_RECOG_ITEM_TEXT            = 3,
    BOY_RECOG_ITEM_IMAGE           = 4
};

enum : BoyRecogDescriptionDetail
{
    BOY_RECOG_DESCRIPTION_BRIEF    = 0,
    BOY_RECOG_DESCRIPTION_DETAILED = 1
};

enum : BoyRecogMessageRole
{
    BoyRecogMessageUser      = 0,
    BoyRecogMessageAssistant = 1
};

#pragma pack(push, 8)

struct BoyRecogEngineInfo
{
    const wchar_t* name;
    BoyRecogCapabilities capabilities;
};

struct BoyRecogRect
{
    int32_t left;
    int32_t top;
    int32_t right;
    int32_t bottom;
};

struct BoyRecogCharInfo
{
    const wchar_t* text;
    BoyRecogRect box;
};

struct BoyRecogMessage
{
    BoyRecogMessageRole role;
    const wchar_t* text;
};

#pragma pack(pop)
```

### 3.1 引擎能力 `BoyRecogCapabilities`

能力用一个 `uint64_t` 位掩码表示，多项能力通过按位或组合。

| 值 | 名称 | 含义及依赖 |
| ---: | --- | --- |
| 1 | `BOY_RECOG_CAP_OCR` | 文字识别总开关，至少支持纯文本 OCR |
| 2 | `BOY_RECOG_CAP_AUTO_OCR` | 支持读屏监视场景下的自动 OCR，依赖 1 |
| 4 | `BOY_RECOG_CAP_PDF_OCR` | 支持 PDF 文字识别场景，依赖 1 |
| 8、16 | 保留 | 当前不得设置 |
| 32 | `BOY_RECOG_CAP_OCR_POSITION` | 支持带位置的结构化 OCR，依赖 1；仍须支持纯文本 OCR |
| 64 | `BOY_RECOG_CAP_OCR_OTHER_TYPES` | 结构化 OCR 支持图标、带描述图标、图片三种非文字类型，依赖 1 和 32 |
| 128、256 | 保留 | 当前不得设置 |
| 512 | `BOY_RECOG_CAP_IMAGE_BRIEF` | 支持简短图片描述 |
| 1024 | `BOY_RECOG_CAP_IMAGE_DETAILED` | 支持详细图片描述，也用于选择图片问答引擎（问答接口可选） |
| 2048、4096 | 保留 | 当前不得设置 |
| 8192 | `BOY_RECOG_CAP_ICON` | 支持单个图标识别，返回图标描述 |

其余未定义位也为保留位，插件当前置零，读屏忽略未知能力位。`512`、`1024`、`8192` 相互独立，不依赖 OCR。

有效引擎必须至少有一个基础能力：

```cpp
(capabilities & (1ULL | 512ULL | 1024ULL | 8192ULL)) != 0
```

`2` 和 `4` 只用于读屏筛选适用场景，不对应额外导出函数。自动识别由读屏重复调用；PDF 由读屏逐页渲染成图片后调用。插件不接收 PDF 文件，也不负责截图、窗口选择或监视调度。

所需能力应检查全部满足，例如自动识别并返回位置需要 `1 | 2 | 32`：

```cpp
(capabilities & requiredCapabilities) == requiredCapabilities
```

### 3.2 引擎信息 `BoyRecogEngineInfo`

| 字段 | 说明 |
| --- | --- |
| `name` | 非空、以 `L'\0'` 结尾的 UTF-16 引擎名称，也是执行接口的引擎选择参数 |
| `capabilities` | 引擎声明的能力位掩码，读屏还会根据导出函数是否存在进行过滤 |

### 3.3 项目类型 `BoyRecogItemType`

| 值 | 名称 | 结果含义及读屏行为 |
| ---: | --- | --- |
| 0 | `BOY_RECOG_ITEM_ICON` | 无描述图标；读屏导航时可另行调用图标识别 |
| 1 | `BOY_RECOG_ITEM_ICON_WITH_LABEL` | 已有描述的图标；`text` 提供可直接朗读的描述，不必再调用图标识别 |
| 3 | `BOY_RECOG_ITEM_TEXT` | 文字项目；`text` 为识别文字 |
| 4 | `BOY_RECOG_ITEM_IMAGE` | 图片项目；读屏导航时可另行调用简短图片描述 |

数值沿用现有内部类型的对应值，`2` 留空。本版插件接口不开放布局区域和未知类型。能力 `64` 支持上述三种非文字类型，但不要求每次识别都返回全部三种类型。

### 3.4 位置 `BoyRecogRect`

坐标相对于输入图片左上角，单位为像素，左上角为 `(0, 0)`。`left`、`top` 包含边界，`right`、`bottom` 不包含边界，宽度为 `right - left`，高度为 `bottom - top`。

有效结果框应位于输入图片范围内，满足 `left < right`、`top < bottom`。插件内部缩放或裁剪图片后，必须把结果映射回原始输入图片坐标。该坐标不是屏幕坐标，也不是相对于当前文字项目的坐标。

### 3.5 字符信息 `BoyRecogCharInfo`

| 字段 | 说明 |
| --- | --- |
| `text` | 单个字符的 UTF-16 字符串，以 `L'\0'` 结尾；使用字符串而不是单个 `wchar_t`，以容纳代理对等多码元字符 |
| `box` | 该字符在原始输入图片上的位置，与项目框使用同一坐标系 |

字符数组按文字顺序排列。引擎没有字符位置信息时允许整个数组为空，不要求推算字符框；项目文字和项目框仍然有效。非文字项目不提供字符数组。

### 3.6 描述详细程度 `BoyRecogDescriptionDetail`

`BOY_RECOG_DESCRIPTION_BRIEF` 表示简短描述，要求能力 `512`；`BOY_RECOG_DESCRIPTION_DETAILED` 表示详细描述，要求能力 `1024`。插件可以分别使用不同模型实现两种模式，不要求两者使用同一模型。

### 3.7 问答消息 `BoyRecogMessage` 和角色 `BoyRecogMessageRole`

| 字段 | 说明 |
| --- | --- |
| `role` | `BoyRecogMessageUser`（`0`）表示用户，`BoyRecogMessageAssistant`（`1`）表示助手；其他值无效 |
| `text` | 非空指针、以 `L'\0'` 结尾的 UTF-16 消息文本 |

消息数组按对话时间顺序排列，每项代表一条完整消息。图片和初始提示词通过图片问答接口的独立参数传递，不在此数组中重复出现。首次调用的数组为空；后续包含首次助手回答、后续各轮用户问题与助手回答，并以本轮用户问题结束。分段返回的助手回答由读屏拼接成一条完整消息后加入历史。

## 4. 回调函数

```cpp
typedef void (__cdecl* BoyRecogEngineListCallback)(
    const BoyRecogEngineInfo* engines,
    size_t engineCount,
    void* userData);

typedef void (__cdecl* BoyRecogTextCallback)(
    const wchar_t* text,
    void* userData);

typedef void (__cdecl* BoyRecogItemCallback)(
    BoyRecogItemType itemType,
    const wchar_t* text,
    const BoyRecogRect* box,
    const BoyRecogCharInfo* chars,
    size_t charCount,
    void* userData);

typedef void (__cdecl* BoyRecogImageDescriptionCallback)(
    const wchar_t* text,
    const wchar_t* prompt,
    bool done,
    void* userData);

typedef void (__cdecl* BoyRecogImageChatCallback)(
    const wchar_t* text,
    const wchar_t* prompt,
    bool done,
    void* userData);
```

### 4.1 引擎列表回调 `BoyRecogEngineListCallback`

获取引擎列表成功时调用一次。

| 参数 | 说明 |
| --- | --- |
| `engines` | 引擎信息数组；`engineCount > 0` 时必须有效 |
| `engineCount` | 数组元素数量；空列表传 `0`，此时 `engines` 为 `nullptr` |
| `userData` | 原样传回获取引擎列表接口的用户数据 |

数组及其名称字符串仅在回调期间有效。

### 4.2 文本回调 `BoyRecogTextCallback`

纯文本 OCR 和图标识别共用此回调，成功时调用一次。

| 参数 | 说明 |
| --- | --- |
| `text` | 完整结果，非空指针，UTF-16，以 `L'\0'` 结尾；无结果传 `L""` |
| `userData` | 原样传回执行接口的用户数据 |

即使底层服务流式输出，插件也必须先聚合完整文本，再调用此回调。

### 4.3 项目回调 `BoyRecogItemCallback`

结构化 OCR 为每个结果项调用一次，按阅读顺序交付。

| 参数 | 说明 |
| --- | --- |
| `itemType` | 文字、图标、带描述图标或图片 |
| `text` | 文字或图标描述；非空指针，以 `L'\0'` 结尾，无文字时传 `L""` |
| `box` | 项目位置，必须有效 |
| `chars` | 可选的字符及字符位置数组；没有字符位置信息时为 `nullptr` |
| `charCount` | 字符数组的元素数，不是 UTF-16 码元数；`chars == nullptr` 时必须为 `0` |
| `userData` | 原样传回执行接口的用户数据 |

`charCount > 0` 时，`chars` 及每项的 `text` 必须有效。项目的 `text`、`box`、`chars` 及字符字符串均只在当前这一次回调期间有效，不能假设它们持续到下一次回调或导出函数返回。

### 4.4 图片问答回调 `BoyRecogImageChatCallback`

| 参数 | 说明 |
| --- | --- |
| `text` | 本次新增文本片段，非空指针、UTF-16、以 `L'\0'` 结尾；没有新增文本时传 `L""` |
| `prompt` | 本轮实际使用的初始提示词，UTF-16、以 `L'\0'` 结尾。每轮调用的第一次回调必须为非空指针且字符串非空；调用时传入非空 `prompt` 时，首次回调必须与传入内容完全相同，只有传入空提示词时插件才补默认值；后续可以传 `nullptr` 或 `L""` 表示沿用首次提示词，再次传非空内容时必须与首次一致 |
| `done` | `false` 表示后续还有回调；`true` 表示本轮最后一次回调 |
| `userData` | 原样传回调用方提供的不透明指针 |

读屏按回调顺序拼接文本；每段必须是新增内容，不能重复发送此前已返回的累计全文。允许只回调一次完整结果并设置 `done == true`。最后一段也可以携带文本，或者用 `L""` 和 `done == true` 单独通知结束。

成功时必须且只能回调一次 `done == true`，之后不得继续回调。`done` 只表示本轮回答结束，不表示整个多轮会话结束，也不替代导出函数返回值。若生成过程中失败，函数返回非零，可以不再发送 `done == true`；函数返回后，本轮调用及全部回调均已结束。

所有回调都在调用导出函数的线程中执行，文本和提示词指针仅在当前回调期间有效，调用方必须及时复制。读屏用实际提示词更新图片后的初始文字消息，后续问答继续传入该提示词；它不作为回答片段追加或单独朗读。即使第一次回调只有结束通知、`text` 为 `L""`，也必须提供非空的实际提示词。接口不额外传入会话或轮次 ID；读屏可通过 `userData` 携带请求上下文，区分每轮结果的归属。该回调不提供取消返回值，插件不得将 `done` 解释为取消请求。

### 4.5 图片描述回调 `BoyRecogImageDescriptionCallback`

简短和详细图片描述共用此回调，同时携带本次描述实际使用的提示词，但返回方式不同：

- 简短描述：成功时只回调一次，`text` 为完整结果，`done` 必须为 `true`；不允许 `done == false` 或分段回调。
- 详细描述：允许按增量文本分段返回，中间回调的 `done` 为 `false`，最后一次为 `true`；也可以只回调一次完整结果，并设置 `done == true`。

| 参数 | 说明 |
| --- | --- |
| `text` | 简短描述为完整结果，详细描述为本次新增片段，非空指针、UTF-16、以 `L'\0'` 结尾；没有新增文本时传 `L""`，不能传 `nullptr` |
| `prompt` | 本次描述实际使用的提示词，非空指针、UTF-16、以 `L'\0'` 结尾；没有提示词时传 `L""`，不能传 `nullptr`。简短描述允许传 `L""` |
| `done` | 简短描述必须为 `true`；详细描述中 `false` 表示后续还有回调，`true` 表示最后一次回调 |
| `userData` | 原样传回调用方提供的不透明指针 |

两个字符串只在本次回调期间有效，调用方必须及时复制。每次回调中的 `prompt` 内容必须保持一致，不随文本片段变化；它不是需要分段拼接的内容。描述文本不自动拼接额外 OCR 结果。BoyOcr 将详细描述的提示词传给主程序，用于“继续追问”时图片后的初始提示词消息；简短描述的提示词不向主程序传递。初始提示词为空时，后续问答仍按 `BoyRecogImageChat` 的约定由插件补默认提示词。

对于详细描述，读屏按回调顺序拼接 `text`，每段必须是新增内容，不得重复发送此前已返回的累计全文。结束回调可以同时携带最后一段文本，也可以传 `L""` 和 `done == true` 单独通知结束；两种模式成功但无结果时，都必须回调一次 `L""` 和 `done == true`。

成功时必须且只能回调一次 `done == true`，之后不得继续回调。最终成功与否仍以导出函数返回值为准；简短描述失败时不调用结果回调；详细描述中途失败返回非零，可以不发送结束回调。已经显示的部分描述可以留在界面，但不得作为完整助手消息加入后续问答历史。所有回调必须在调用线程执行，并在导出函数返回前结束。

此回调替代图片描述原先使用的 `BoyRecogTextCallback`，插件需要按新签名重新编译；OCR 和图标识别回调不变。

## 5. 导出函数

共定义 9 个固定导出名称：初始化、退出清理和引擎列表三个接口必须提供，五个识别执行接口按能力提供，设置接口可选。下列声明位于 `extern "C"` 中；实现时通过 `.def` 文件或正确的导出配置提供同名导出。

```cpp
extern "C" {

int __cdecl BoyRecogInit();
int __cdecl BoyRecogUninit();

int __cdecl BoyRecogSettings(const wchar_t* engineName);

int __cdecl BoyRecogGetEngineList(
    BoyRecogEngineListCallback callback, void* userData);

int __cdecl BoyRecogOcrText(
    const wchar_t* engineName,
    const char* imageData, size_t imageSize,
    BoyRecogTextCallback callback, void* userData);

int __cdecl BoyRecogOcrItems(
    const wchar_t* engineName,
    const char* imageData, size_t imageSize,
    int includeOtherTypes,
    BoyRecogItemCallback callback, void* userData);

int __cdecl BoyRecogDescribeImage(
    const wchar_t* engineName,
    const char* imageData, size_t imageSize,
    BoyRecogDescriptionDetail detail,
    BoyRecogImageDescriptionCallback callback, void* userData);

int __cdecl BoyRecogImageChat(
    const wchar_t* engineName,
    const char* imageData, size_t imageSize,
    const wchar_t* prompt,
    const BoyRecogMessage* messages, size_t messageCount,
    BoyRecogImageChatCallback callback, void* userData);

int __cdecl BoyRecogRecognizeIcon(
    const wchar_t* engineName,
    const char* imageData, size_t imageSize,
    BoyRecogTextCallback callback, void* userData);

}
```

### 5.1 `BoyRecogInit`

加载插件时调用，无参数。初始化插件资源，成功返回 `0`。初始化失败应自行清理已创建资源，返回非零；读屏不调用执行接口，并卸载该插件。不要在 `DllMain` 中执行耗时初始化或网络请求。

### 5.2 `BoyRecogUninit`

插件卸载前调用，无参数。读屏保证本插件的执行调用和回调已经结束。插件应释放模型、网络连接、线程等资源，成功返回 `0`，失败返回插件定义的非零错误码。

无论返回值如何，插件都必须确保没有线程或回调继续执行插件代码；非零返回值不表示读屏必须保留 DLL。成功初始化的插件即使后续引擎列表获取失败或没有有效引擎，也会先退出清理再卸载。

### 5.3 `BoyRecogGetEngineList`

返回插件提供的全部引擎及能力，初始化成功后调用。

| 参数 | 说明 |
| --- | --- |
| `callback` | 引擎列表回调，不能为 `nullptr`；成功时调用一次 |
| `userData` | 用户数据，允许为 `nullptr` |

成功返回 `0`。失败返回非零且不回调。空列表可以成功返回，但插件没有有效引擎时会被读屏丢弃。插件名称与引擎名称是不同概念，一个插件允许返回多个引擎。

### 5.4 `BoyRecogOcrText`

对图片进行文字识别，返回纯文本。引擎必须具备能力 `1`。

| 参数 | 说明 |
| --- | --- |
| `engineName` | 引擎列表中返回的 UTF-16 名称 |
| `imageData`、`imageSize` | 图片编码数据及字节数 |
| `callback` | 文本回调，不能为 `nullptr`；成功时调用一次 |
| `userData` | 原样传给回调 |

返回的文本按阅读顺序组织，需要换行时使用换行符。没有识别到文字可回调空字符串并返回 `0`。不返回图标、图片占位文字或位置数据。

### 5.5 `BoyRecogOcrItems`

对图片进行结构化文字识别，逐项返回类型、文字、项目位置及可选字符位置。引擎必须具备 `1 | 32`。

| 参数 | 说明 |
| --- | --- |
| `engineName` | 引擎列表中返回的 UTF-16 名称 |
| `imageData`、`imageSize` | 图片编码数据及字节数 |
| `includeOtherTypes` | `0` 只返回文字项目，`1` 允许同时返回三种非文字项目；其他值无效 |
| `callback` | 项目回调，不能为 `nullptr`；每个项目调用一次 |
| `userData` | 每次回调均原样传回 |

`includeOtherTypes == 1` 时还要求能力 `64`。不支持时返回非零，不得静默忽略该参数。返回非文字项目不要求每次图片都有这些类型；没有项目可以不回调并返回 `0`。

字符位置可以缺省：`chars == nullptr` 且 `charCount == 0`，但项目自身的位置必须存在。函数最终返回非零时，本次所有已交付项目均视为失败结果，由调用方丢弃。

### 5.6 `BoyRecogDescribeImage`

生成图片的自然语言描述。

| 参数 | 说明 |
| --- | --- |
| `engineName` | 引擎列表中返回的 UTF-16 名称 |
| `imageData`、`imageSize` | 图片编码数据及字节数 |
| `detail` | `0` 简短描述，需要 `512`；`1` 详细描述，需要 `1024`；其他值无效 |
| `callback` | `BoyRecogImageDescriptionCallback`，不能为 `nullptr`；简短描述只回调一次完整结果且 `done == true`；详细描述允许分段并以一次 `done == true` 结束，见第 4.5 节 |
| `userData` | 原样传给回调 |

不支持请求的详细程度时返回非零，不自动切换到另一种模式。此接口仅详细描述支持流式分段，简短描述须一次返回完整结果；不传递会话 ID，也不提供多轮问答；多轮图片问答使用 `BoyRecogImageChat`。

### 5.7 `BoyRecogRecognizeIcon`

将输入图片作为一个图标进行识别，返回图标名称或描述，例如“搜索”“关闭”。引擎需要能力 `8192`。

| 参数 | 说明 |
| --- | --- |
| `engineName` | 引擎列表中返回的 UTF-16 名称 |
| `imageData`、`imageSize` | 单个图标的图片编码数据及字节数，由调用方准备 |
| `callback` | 文本回调，不能为 `nullptr`；成功时调用一次 |
| `userData` | 原样传给回调 |

此接口不负责从整张截图中定位多个图标。识别正常完成但没有匹配标签时，回调空字符串并返回 `0`；模型加载失败或执行错误等返回非零且不回调。

### 5.8 `BoyRecogSettings`

可选接口，用于显示指定引擎的设置界面，例如配置 API 密钥、服务地址或模型参数。接口形式与翻译插件的设置接口一致。读屏识别引擎管理器提供“引擎设置”按钮；选中具有该接口的插件引擎时可用。

```cpp
int __cdecl BoyRecogSettings(const wchar_t* engineName);
```

| 参数 | 说明 |
| --- | --- |
| `engineName` | 引擎列表返回的非空 UTF-16 名称，以 `L'\0'` 结尾；插件应检查该引擎是否存在 |

读屏通过插件名定位 DLL，再将选中的引擎名称传入此接口，不需要向插件传入插件名。插件自行创建设置界面、校验输入，并将配置保存到第 1.2 节约定的文档目录下，无需结果回调或 `userData`。

插件接口仍为同步调用，由 BoyOcr 在独立线程调用；设置界面关闭后返回。主程序界面线程不等待设置窗口关闭。正常关闭（包括用户取消修改）返回 `0`，引擎名称无效、界面创建失败等情况返回插件定义的非零错误码。用户取消修改时不得保存本次修改。

BoyOcr 的 `BoyOcrPluginSettings(pluginName, engineName)` 返回 `0` 表示已启动设置调用，不表示设置操作已经完成；插件最终返回的错误由 BoyOcr 记录日志。同一插件的设置窗口未关闭时，再次请求返回忙；退出清理会等待设置调用完成后再卸载插件。

设置接口必须在插件初始化成功后、退出清理前调用。插件不得在函数返回后保留 `engineName` 指针；若设置与识别调用共享配置，应保证并发访问安全。

此接口不占用识别能力标志位。未导出时，读屏不提供可用的设置入口，但仍可正常使用该插件的识别功能。

### 5.9 `BoyRecogImageChat`

基于图片、初始提示词和消息历史生成本轮回答，支持分段返回。引擎需要能力 `1024`（`BOY_RECOG_CAP_IMAGE_DETAILED`），不新增能力位。`BoyRecogImageChat` 为可选接口。声明 `1024` 不保证支持问答：缺少该接口或具体引擎不支持问答时，问答调用失败，但普通详细描述仍可用。

| 参数 | 说明 |
| --- | --- |
| `engineName` | 引擎列表返回的非空 UTF-16 名称 |
| `imageData`、`imageSize` | 每轮均传入原图片的完整编码数据及字节数，必须支持 PNG；不能为空 |
| `prompt` | 会话的初始提示词，UTF-16；为 `nullptr` 或空字符串时，由插件补上默认提示词 |
| `messages` | 图片与初始提示词之外的完整消息历史，包含本轮用户问题；`messageCount > 0` 时必须有效 |
| `messageCount` | 消息数组元素数量；首次调用为 `0`，此时 `messages` 可以为 `nullptr` |
| `callback` | 图片问答分段回调，不能为 `nullptr`；具体语义见第 4.4 节 |
| `userData` | 每次回调均原样传回，允许为 `nullptr` |

每次调用生成一轮回答，调用方式如下：

1. 首轮：传入图片和初始提示词，消息历史为空。提示词为空时由插件补默认提示词；本轮第一次回调必须返回实际使用的非空提示词。调用方复制并保存它，作为图片后的初始文字消息。
2. 第二轮：再次传入相同图片，并将已经保存的实际提示词完整传入 `prompt`，不能再省略。消息数组为 `[首次助手回答, 本轮用户问题]`。
3. 后续各轮：再次传入图片和初始提示词，消息数组包含首次助手回答、其后完整问答及本轮用户问题，保持原始顺序。

`prompt` 始终是初始提示词，不是每轮的新问题；后续问题放在消息数组末尾。调用方收到首次回调返回的实际提示词后，应将其保存为图片后的初始文字消息，并在后续每轮调用中通过 `prompt` 参数完整传入，不能因插件处理过上一轮而省略。图片、初始提示词和 `messages` 数组共同构成完整消息链。

注意：允许省略的是**同一轮第一次回调之后的回调参数 `prompt`**，不是下一轮调用的输入参数。每轮第一次回调仍须返回非空提示词；当该轮输入 `prompt` 非空时，回调值必须与输入完全相同。插件不能以已经缓存上一轮提示词为由要求调用方省略上下文。

例如首轮输入 `prompt = nullptr`，插件使用默认值“请详细描述这张图片。”，则本轮第一次回调必须返回该字符串。调用方保存它；第二轮调用传入同一图片、`prompt = L"请详细描述这张图片。"`，以及 `[首次完整助手回答, 第二轮用户问题]`。第二轮第一次回调仍返回同一提示词，之后的分段回调才允许用 `nullptr` 或 `L""` 省略。错误和未完成回答不加入这个历史数组。

读屏界面中的图片和初始提示词仍占据前两条消息。适配插件调用时，将这两条分别提取为图片和提示词参数，其余消息作为历史数组传入。每轮发送完整消息链，不预先为插件裁剪或压缩；插件根据模型的上下文长度和服务协议，自行决定如何压缩、裁剪或组织请求，且不得修改传入的原始数据。

插件可以把图片与提示词合并为一条多模态消息，也可以分别构造消息，具体由插件适配底层模型；接口不规定服务端的消息格式。插件必须同时处理独立参数和消息数组，不能遗漏图片、初始提示词或本轮问题。

插件接口为同步调用，BoyOcr 在独立工作线程中调用并接收分段结果，主程序界面无需等待本轮回答完成。插件不得在函数返回后继续回调或保留输入指针。每轮输入已包含完整上下文，不要求插件保留跨轮会话状态，也不增加创建或销毁会话的导出函数。

成功返回 `0`，并按第 4.4 节结束回调。参数无效、引擎不支持、网络或模型执行失败时返回插件定义的非零错误码，不得将错误提示作为正常回答回调。

对于引擎存在、输入及回调有效、但该引擎不支持问答的情况，插件应先用 `callback(L"", actualPrompt, true, userData)` 返回实际提示词，再返回非零错误码。输入提示词非空时 `actualPrompt` 必须与输入相同；输入为空时返回该引擎的非空默认提示词。调用方先更新初始提示词，再根据函数的非零返回值显示错误；空文本不创建助手消息，`done == true` 也不能被当作成功回答加入历史。若整个 DLL 缺少问答导出函数，则无法通过此接口获取默认提示词。读屏界面可先显示内置 VIVO 的描述提示词作为兜底，但首次请求插件默认提示词时仍传空；收到插件返回的实际提示词后替换界面及消息链中的初始提示词，插件未返回时保留兜底内容。

以下 `.def` 文件列出全部接口。插件不提供某项执行能力时，可以删除相应执行函数的导出项，前三项必须保留；无需设置界面时，可省略 `BoyRecogSettings`。

```def
LIBRARY BoyRecogExample
EXPORTS

```

## 6. 能力校验和插件淘汰规则

读屏通过固定导出名查找函数，结合每个引擎声明的能力计算最终可用能力：

| 条件 | 处理 |
| --- | --- |
| 缺少 `BoyRecogInit`、`BoyRecogUninit` 或 `BoyRecogGetEngineList` 任意一个 | 插件无效，不进入识别调用 |
| 初始化或获取引擎列表返回非零 | 插件不可用，按生命周期规则清理卸载 |
| 缺少 `BoyRecogOcrText` | 清除 `1、2、4、32、64` |
| 缺少 `BoyRecogOcrItems` | 清除 `32、64` |
| 缺少 `BoyRecogDescribeImage` | 清除 `512、1024` |
| 缺少 `BoyRecogImageChat` | 不清除能力位，问答调用返回失败，普通详细描述仍可用 |
| 缺少 `BoyRecogRecognizeIcon` | 清除 `8192` |
| 缺少 `BoyRecogSettings` | 设置入口不可用，不清除任何识别能力，不因此丢弃插件 |
| 引擎未声明 `1` | 清除依赖 OCR 的 `2、4、32、64` |
| 引擎未声明或已清除 `32` | 清除 `64` |
| 过滤后不包含 `1、512、1024、8192` 中任何一项 | 丢弃该引擎 |
| 插件没有任何有效引擎 | 退出清理并卸载插件 |

函数存在不会自动增加引擎未声明的能力。例如同一个图片描述函数存在，但某引擎仅声明 `512`，读屏仍不能向该引擎请求详细描述。

`1024` 只要求详细描述接口存在。图片问答沿用该能力进行引擎选择，执行时检查问答接口；接口存在但特定引擎不支持问答时，插件返回非零错误码。

读屏筛选能力不能替代插件参数检查。插件仍应检查引擎名称、图片、回调和选项是否有效，并拒绝调用不支持的能力。

## 7. 开发检查要点

- DLL 为 x86，名称匹配 `BoyRecog*.dll`，具有非空 `ProductName` 和 `ProductVersion`。
- 导出名称和 `__cdecl` 调用约定正确，数据结构使用本文的字段、宽度和对齐方式。
- 引擎列表声明与实际实现一致，不设置保留位。
- 图片按显式长度处理，引擎名称和结果文字均使用 UTF-16。
- 所有回调在导出函数返回前完成，结果内存无需读屏释放。
- 纯文本 OCR 和图标识别一次回调完整结果；结构化结果逐项回调，缺少字符位置时传空数组和零数量。
- 简短图片描述只回调一次完整结果，`done` 必须为 `true`；详细描述和图片问答允许增量分段回调，成功时必须且只能以一次 `done == true` 结束。
- 详细描述分段回调的 `prompt` 保持一致。
- 问答接口可选，不支持问答不得影响普通详细描述。
- 图片问答每轮接收图片、可空初始提示词及完整后续消息历史，插件自行适配多模态消息格式和上下文压缩。
- 位置统一映射回原始输入图片，不返回屏幕坐标。
- 错误返回非零，不能将错误消息伪装成成功识别文本。
- 退出前结束所有线程和请求，避免 DLL 卸载后仍执行插件代码。
